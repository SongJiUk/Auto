# 작업 정리

## 1. 사실 모으기 (기억이 아니라 기록에서)
```powershell
date
git log --since="today 00:00" --oneline
git status --short
git diff --stat
```
- 날짜·요일은 반드시 `date` 결과를 쓴다. 머리로 계산하지 않는다.
- 이번 세션에서 실행한 테스트·빌드·배포 결과만 "완료/확인"으로 적는다. 실행 안 한 것은 "확인 안 됨"으로 적는다.

## 2. CLAUDE.md 갱신 (프로젝트 루트)
1. **남은 할 일**: 끝낸 항목은 `[x]` 로 바꾸거나 지운다. 새로 생긴 일을 "사용자가 할 것 / Claude 가 할 것"으로 나눠 추가한다. 머리말 날짜(`(YYYY-MM-DD 기준, …)`)를 오늘로.
2. **마지막 작업**: 기존 "마지막 작업 (날짜)" 제목을 "이전 작업 (날짜)"로 바꾸고, 그 위에 새 "마지막 작업 (오늘)" 을 쓴다. 기존 문체를 따른다:
   - 바뀐 기능을 한 줄씩, 관련 클래스·메서드 이름을 백틱으로 (`MainViewModel.RefreshUsage`)
   - 확인 방법과 "아직 미확인" 항목을 따로
3. 위쪽 고정 섹션(기술 스택, 엑셀 편집 규칙, 개인정보, 실행 폴더)은 사용자가 바꾸자고 한 게 아니면 건드리지 않는다. 바뀐 사실(예: exe 이름)이 있으면 고칠지 묻는다.
4. CLAUDE.md가 800줄을 넘으면 오래된 "이전 작업"을 `docs/작업기록.md` 로 옮기자고 제안한다 (직접 옮기지 않음).

## 3. 작업일지
- 위치: `~/.claude/work-log/YYYY-MM-DD.md` (있으면 덧붙인다).
- 형식:
  ```markdown
  ## 서식채우기 (FormFiller)
  ### 완료
  - …
  ### 다음 작업
  - …
  ### 막힌 부분
  - … (없으면 생략)
  ```
- 개인정보(이름·주민등록번호·계좌번호), API 키, 현장 파일 내용은 적지 않는다.
- 블로그(티스토리 개발 일지)용 소재가 될 삽질·에러가 있었으면 "블로그 소재" 한 줄로 따로 적는다.

## 4. 커밋 (확인 필요)
- CLAUDE.md 변경은 `docs: 작업 기록 갱신` 형식으로 커밋할지 사용자에게 묻는다. push도 따로 묻는다.
- work-log는 `~/.claude` 쪽 저장소에서 따로 처리한다(사용자 지시에 따름).

## 5. 보고
- 갱신한 파일 경로와 바뀐 섹션, 다음 세션 시작 때 읽을 "다음 작업" 3줄 요약.
