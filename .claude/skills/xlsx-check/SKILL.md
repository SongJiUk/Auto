# 엑셀 검증

CLAUDE.md "검증 규칙"을 절차로 만든 것이다. **파일은 읽기만 한다.** 원본(`samples/`, 드라이브 `서식\`)과 결과 파일 모두 수정하거나 다른 프로그램으로 다시 저장하지 않는다.
(openpyxl로 저장하면 그림·도형이 사라지므로 openpyxl은 쓰더라도 `read_only`/`data_only` 읽기에만 쓴다.)

## 개인정보
- 출력 파일에는 이름·주민등록번호가 들어 있다. **셀 값을 대화에 그대로 옮기지 않는다.** 칸 주소, 개수, 합계 숫자만 보고한다.
- 파일을 외부(API, 웹)로 보내지 않는다.

## 1. 비교 대상 고르기
| 결과 파일 | 비교 기준 |
|---|---|
| `UsePreviousAsBase` 켜진 문서 | 앞 날짜 출력 파일 (없으면 서식) |
| 그 외 | `config.json` 의 `templateFile` 서식 |

실사용 위치: 서식 `G:\내 드라이브\FormFiller\서식\`, 결과 `G:\내 드라이브\FormFiller\output\`. 개발 중에는 `samples\` → `output\`.

## 2. 구조 비교 (자동)
```powershell
python -X utf8 -I .claude\skills\xlsx-check\scripts\compare_xlsx.py "<기준.xlsx>" "<결과.xlsx>"
```
- 종료 코드 `0` 구조 동일 / `1` 차이 있음 / `2` 열리지 않음(손상)
- `차이`: 그림·도형 개수, 병합, 열 너비, 시트 목록, 인쇄 영역, 사라진 수식, 결과 파일의 fullCalcOnLoad 꺼짐
- `참고`: 이미지 파일 수 변화·그림 위치 이동(사진 교체·그림 위치 필드 사용 시 정상), 바뀐 칸 주소 목록
- 바뀐 칸 목록이 `config.json` 에 지정한 칸(`cell`, `cells`, 표 범위)과 맞는지 대조한다. 지정 안 한 칸이 바뀌었으면 보고한다.
- 서식 원본끼리 비교하면 "fullCalcOnLoad 꺼짐"이 나오는 게 정상이다(원본엔 플래그가 없음). 프로그램이 만든 파일에서 나오면 문제다.

## 3. 합계 대조 (수식과 별개로 직접 계산)
수식 캐시값은 낡았을 수 있으니(fullCalcOnLoad로 엑셀이 열 때 다시 계산) 믿지 않는다.
- 장비·인원 표: `누계 = 전일 + 금일` 을 줄마다 직접 계산해 결과 파일의 값과 비교한다.
- 전일 칸 = 앞 날짜 파일의 누계 칸인지 확인한다 (주말 건너뜀, `FindPreviousFile` 규칙).
- 합계 줄은 각 줄을 더한 값과 비교한다.
- 이런 대조가 필요하면 `FormFiller.Tests` 에 xUnit 테스트로 남기는 걸 먼저 제안한다 (테스트명 `메서드_상황_기대결과`).

## 4. 눈으로 확인 (렌더링)
- LibreOffice가 설치돼 있지 않다 (2026-11-18 확인: `soffice` 없음). 설치돼 있으면:
  `soffice --headless --convert-to pdf --outdir <scratchpad> "<결과.xlsx>"` 후 원본 PDF와 페이지별 비교.
- 없으면 사용자에게 결과 파일을 Excel로 열어 확인해 달라고 요청한다. 확인 항목: 사진 위치·크기, 도장 이미지, 인쇄 미리보기 한 페이지 맞춤, 날짜 형식(`2026년 11월 04일 수요일` / `2026.11.04`).

## 5. 보고
- 실행한 명령과 종료 코드, `차이` 항목 전체, 바뀐 칸 수.
- 렌더링 비교를 못 했으면 "눈으로 확인 안 함"이라고 적는다. 검증하지 않은 것은 검증했다고 쓰지 않는다.
