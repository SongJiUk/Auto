# 이미 정한 것과 그 이유 (다시 묻지 말 것)

## 만드는 것
- 매일 반복하는 서식 채우기 프로그램. 사용자가 서식 파일과 칸을 한 번 설정하면, 매일 값을 넣어 문서를 만든다.
- 매일 달라지는 인원·장비 입력까지 없애는 것이 목표가 아니다.

## 기술 선택
| 결정 | 이유 |
|---|---|
| Unity 사용 안 함 | 파일 끌어다 놓기, 파일 선택 창, 한글 입력(IME) 처리가 불안정하거나 직접 만들어야 함. 데스크톱 업무 도구에 맞지 않음 |
| 웹 앱 + Supabase 보류 | 하려는 일이 엑셀·한글 파일 읽기·쓰기라서 로컬 처리가 맞음. 이름 등 개인정보를 서버에 올리지 않기 위해 |
| C# WPF (.NET 8) | 사용자가 C#을 알고, 화면을 현대적으로 꾸미기 좋음 |
| Open XML SDK | 이미지·도형·도장을 보존하면서 셀 값만 바꾸려는 목적 |
| 동기화는 클라우드 폴더 | 두 PC에서 같은 폴더를 연결하면 되고, 직접 동기화 기능을 만들 필요가 없음 |
| 모바일은 후순위 | PC 먼저. 모바일은 사진과 입력 전송 정도로 나중에 |
| Claude API 기능은 후순위 | 출근부 사진 이름 인식은 비용, 개인정보 전송, 오인식 문제가 있음. 항상 "AI 제안 -> 사람 확인 -> 저장" 순서 |
| 사진은 기존 이미지 교체 방식 | 이미 자리·크기가 잡혀 있어서 위치가 유지됨. 먼저 시험해서 확인 |

## 사용자 환경
- 윈도우 PC 두 대. 폰은 모바일 확장 시 사용.
- 한글 파일은 `.hwpx` (4단계).
- 현장: 오전다구역 재개발 철거현장. 업체: ㈜참마루건설.

## 별도로 이미 완성된 것: 노임대장 엑셀 (5단계 연동 대상)
- 파일명: `오전다구역_노임대장_2026_10월분_자동화.xlsx` (이 프로젝트 폴더에는 들어 있지 않음)
- 시트: `설정`(요율·기준·공휴일), `입력`(사람 한 줄, 1~31일 출역), `전월`(전월 기록), 월별 노임대장(수식으로만 채워짐)
- 입력은 `입력` 시트에서만 한다. 노임대장 시트는 직종(현장관리, 장비, 비계) -> 가나다순으로 자동 정렬된다.
- 공제 기준은 사용자가 제공한 `노임대장 기준.pdf`를 따른다.
  - 소득세: (일당-15만원) x 일수 x 2.7%, 1,000원 이하 면제, 지방소득세는 소득세의 10%
  - 국민연금: 4.75%, 기준소득월액 하한 41만원 ~ 상한 659만원(2026.07~), 만 60세 생일이 속한 달까지
  - 건강보험 3.595%, 장기요양은 건강보험료의 13.14%
  - 고용보험 0.9%, 만 65세 생일부터 면제, F-4/H-2/E-9는 임의가입
  - 국민연금·건강보험: 월 소득 220만원 이상이면 공제. 그 미만은 [1일 출근 또는 전월 근무이력] + [월 8일 이상(타 현장 합산 가능)]
- 5단계에서는 이 `입력` 시트의 출역 칸을 채우는 방식으로 연동한다. 노임대장 시트에 직접 쓰지 않는다.

## 규칙을 정해 가는 방식
- 사용자는 서식마다 "이 칸을 이렇게 바꿔 달라"고 알려 준다. 불분명한 규칙은 추측하지 말고 설정으로 만들거나 질문한다.
- TBM일지 내용의 기준은 사용자가 나중에 정해 준다.

## 사용자가 요청하지 않은 것 (하지 말 것)
- 서식의 디자인 변경, 문구 수정
- 서버나 외부 서비스 연결
- 기획서에 없는 기능 추가
